# Classroom review process

## Peer Review Plan

A classmate will review the project and research site.

I will ask the reviewer to complete three specific tasks.

### Task 1 — Open a Source

The reviewer will open one original research source and determine whether it actually supports the claim made on the research site.

### Task 2 — Explain a Design Choice

The reviewer will explain why NeuroNet uses a brain/network interface instead of a standard list of mini-games.

### Task 3 — Identify an Assumption

The reviewer will identify something the project currently assumes about the user without enough evidence.

Examples:

- Users will understand the network metaphor.
- Users will want to return to completed skills.
- Short mini-games will feel more approachable.
- Progress visualization will motivate continued play.

Feedback will be recorded as a GitHub Issue.

---


## GitHub Issue Process

Each meaningful review item will be documented in GitHub.

Possible decisions include:

### Implement

The feedback identifies a useful improvement that fits the project scope.

### Investigate

The feedback raises an important question that needs more testing.

### Defer

The feedback is valid but outside the current project scope.

### Decline

The feedback does not fit the project's research question or design goals.

Accepted feedback will link to the resulting documentation or code change. The reviewer will retry the relevant feature after implementation when appropriate.

Resolved issues will be closed. Unfinished work will remain open with a documented next step.
